# Continuous improvement from user feedback

When the user expresses frustration or dissatisfaction, repeats a correction, or says an issue must not recur:

1. Acknowledge the feedback and address the immediate issue.
2. Before ending the response, visibly assess whether prevention is warranted; fixing the immediate issue alone is not enough.
3. Verify the cause and inspect relevant rules, skills, extensions, tests, and tooling. Repair an existing mechanism instead of layering on duplicate guidance.
4. For a repeatable failure, offer one evidence-based fix: cause, change, and location. Use the narrowest reliable mechanism—global or project rule, skill, mechanical guard, test, or code fix—and prefer enforcement over prose.
5. For a one-off issue, explicitly say why no persistent change is justified.
6. Do not apply the prevention fix without user approval unless already requested. Keep project-specific guidance project-local.
